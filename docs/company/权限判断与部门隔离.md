# 权限判断与部门隔离

本文定义资源访问判断。身份停用、旧凭证撤销、来源选择和事实时效由[同步文档](./组织同步与身份状态.md#identity-lifecycle)负责；这里消费其可信凭证结果，不另写一套状态机。

## 资源、动作与角色

一次决策的输入为主体、可信认证来源、当前 Tenant、源 Tenant、资源、动作和访问路径。先将 Document、Chunk、Wiki、附件和引用解析到源知识库，再计算相应资源动作。

| 资源 | 动作 |
| --- | --- |
| Workspace | `view`、`manage_members`、`manage_settings` |
| KnowledgeBase | `view`、`query`、`create`、`edit_metadata`、`delete`、`share` |
| Knowledge content | `view`（含已授权预览）、`download_original`、`ingest`、`edit_content`、`delete` |
| Agent | `view`、`run`、`edit`、`share` |
| Integration | `view`、`manage` |
| API Key | `view`、`create`、`revoke` |

动作与资源类型一起解释：删除文档不等于删除知识库；编辑内容不包含修改知识库设置。路由只负责解析资源和动作，不能把 HTTP 方法直接当成最终授权依据。

| Tenant 角色 | 在现有 RBAC 中的定位 | 部门授权不能改变的限制 |
| --- | --- | --- |
| `viewer` | 读取 | 不因有部门编辑 grant 获得写入能力 |
| `contributor` | 参与创建、维护 | 编辑仍需通过资源创建者或管理员守卫 |
| `admin` | 管理资源、成员及配置 | 有效性取决于可信角色贡献，不由部门负责人标记产生 |
| `owner` | 空间所有者能力 | 由受控人工/平台流程授予，不由目录同步产生 |

具体动作仍使用现有角色映射及服务守卫，表格不是新的全角色能力表。公司部门策略不能修改系统管理员身份或知识库所属 Tenant。

<a id="decision-order"></a>
## 判断顺序

```text
1. 验证主体和凭证
2. 解析资源及适用访问路径
3. 检查每条路径的准入条件
4. 检查用户 / 资源 / 动作 / 路径的资源范围
5. 计算来源 grant，并应用该路径的动作上限
6. 合并同一真人主体已经通过的路径
7. 返回结果与依据，再执行业务操作
```

身份、凭证或全局阻断失败，以及请求共有的必要状态不可读时，拒绝整个请求。单条路径的准入、范围、动作检查失败或其依赖状态不可读，只关闭该路径，其他合法路径继续独立计算并取 OR。例如 T1 用户不是 T0 成员，但仍可通过合法的 K4 组织共享访问。不能用缓存中的旧允许结果跳过当前检查。

第 1 步输出 `human_session_usable` 或 `api_key_principal_dependency_pass`，具体凭证判断使用[同步文档](./组织同步与身份状态.md#freshness)。认证来源由可信会话或 Key 依赖元数据提供，不由请求中的 `provider_id` 选择。

真人路径可以有多个；API Key 是独立主体，只计算自己的路径。显式 Agent 请求还需满足该指定 Agent 的入口约束，不能在失败后改走组织共享或另一个 Agent。

## 访问路径与前置条件

| 路径 | 必须满足 | 不自动获得 |
| --- | --- | --- |
| `human_tenant_member` | 当前 Tenant 等于资源 Tenant，目标成员有效，角色贡献有效 | Tenant 成员资格不等于全部门资源可见 |
| `human_organization_share` | 当前 Tenant 成员有效，接收 Tenant 为组织有效成员，KB share 有效 | 不要求用户加入源 Tenant，也不授予源空间管理能力 |
| `human_shared_agent` | 当前 Tenant 成员有效，Agent 可访问/共享有效，源 Tenant 和 KB 选择范围匹配 | Agent 可运行不等于可查询其全部 KB |
| `api_key` | principal、Key、到期、撤销、能力与资源 scope 有效；声明的身份依赖有效 | 不使用真人部门并集或管理员范围例外 |

组织角色是 Tenant 在 Organization 中的角色，不是员工部门角色。成员、组织共享与 Agent 三条路径分别计算各自前置条件及上限，再合并已通过结果。

路径 gate 是结构性准入：缺少成员关系、共享撤销、来源不匹配、Key scope 不符不能由额外用户 grant 修复。状态、角色或共享记录必须从当前可信状态读取。

<a id="resource-scope"></a>
## 部门资源范围

隔离源 Tenant 中，范围判断独立于动作 grant：

```text
resource_scope_pass(user, resource, action, access_path)
```

它回答“这次请求能否进入这个资源”，不是“角色是否含读取动作”。范围许可与动作许可都通过才允许访问。

### 内部成员

内部主体按源企业身份及成员贡献判定，不只看 `active_tenant_id`。内部员工切换到另一个合法 Tenant，仍需满足源 Tenant 部门范围；不能因切换空间被当作外部访客。人工 suspended 不移除内部身份，必要归属不可读则拒绝。

| 范围情形 | 具体判断 |
| --- | --- |
| 部门绑定 | 用户属于当前选定来源的有效部门，资源/action/path 绑定匹配 |
| 用户范围许可 | 有明确用户、资源、动作、路径、有效期的许可；仅开放声明范围 |
| 无匹配绑定或许可 | 默认拒绝，包括资源创建者和普通 contributor |
| `tenant_public` | 仅对源 Tenant 的有效内部成员开放明确 `public_actions`；一期为 `view/query` |
| 人工源 Tenant admin/owner | 当前 Tenant 等于源 Tenant，可豁免部门范围；记录例外命中 |

`tenant_public` 不是匿名访问，也不是跨 Tenant 公共。无范围记录和空绑定按 restricted 处理，不能把空值解释成公共。

人工 admin/owner 例外只豁免部门资源范围，不豁免凭证、封禁、路径或共同安全上限。部门负责人、外部管理员、系统管理员标记均不自动获得该例外；系统管理员另按明确平台策略验收。

最小示例：U1 是 T0 viewer，属于 P1:D1；K3 只绑定 P1:D2。U1 即使从 Tenant RBAC 得到 `view`，`resource_scope_pass` 仍失败，因此不能读 K3。

### 跨 Tenant 共享与导出

外部接收主体必须同时命中有效 share/Agent 和源 Tenant 批准的导出许可。导出许可固定：

```text
source_tenant + receiver_tenant + resource + actions
+ access_path + organization / agent + expiry + policy_version
```

批准 O1 上 K4 的只读导出，不表示批准其他组织、其他 Agent 或其他 KB。公共资源也需单独导出许可。

源企业内部员工通过接收 Tenant 访问时，既检查部门范围，又检查导出许可；纯外部接收主体检查导出许可，不要求加入源部门。这两类身份不能随客户端选择路径而互换。

### 创建、子资源与机器访问

Workspace 管理动作和资源创建尚无现成目标，不套用“未绑定 KB”检查，使用各自 RBAC 与创建策略。普通成员创建 KB 时，必须按已批准模板原子生成初始范围绑定；模板缺失或不能绑定则拒绝创建。不能先创建一批无法访问的资源，再靠后续同步补许可。

知识内容、下载、图片及引用从源 KB 继承范围判断；动作依其资源类型判断，不通过子资源 ID 绕过 KB 范围。

API Key 使用批准的资源 scope，不继承用户部门范围或人工管理员例外。`full_access` 也不免除 principal、撤销和平台安全检查；它在隔离 Tenant 可表达的范围须经过 P5 验收。

<a id="grants-and-limits"></a>
## 来源授权与动作上限

### 哪些来源参与

真人请求使用选定认证来源的有效成员与部门贡献，以及仍有效的人工贡献。一期不把 P1/P2 的部门关系混合取并集。投影表中的最高角色不能替代本次请求的来源筛选。

外部事实和关系需满足[同步时效判断](./组织同步与身份状态.md#freshness)。无效来源保留审计记录，但不能贡献能力；某个许可到期只移除该许可，不使其他独立有效许可一并失效。

### 部门 grant 的局部限制

部门策略按资源、动作和路径配置，多个匹配部门的允许动作取并集，然后只对部门 grant 应用以下上限：

```text
bounded_department_grants =
    eligible_department_grants
    INTERSECT department_grant_action_limit
```

部门不能授予 Owner、系统管理员、`manage_members`、`manage_settings`，也不能授予知识库的 `edit_metadata/delete/share`。`create` 必须独立配置和验证，不能由“负责人”自动推导。

这些限制只裁剪部门 grant，不与全部授权并集求交。人工 admin 同时属于普通部门时，人工 `manage_members/manage_settings` 保留；部门绑定也不会给普通 viewer 增加管理能力。

### Tenant 成员路径

```text
member_grants =
    eligible_tenant_rbac_grants
    UNION bounded_department_grants
    UNION eligible_user_grants

member_limits =
    tenant_rbac_ceiling
    INTERSECT resource_ownership_ceiling
    INTERSECT platform_security_ceiling

member_allow =
    human_session_usable
    AND member_path_gate_pass
    AND resource_scope_pass
    AND action IN (member_grants INTERSECT member_limits)
```

`tenant_rbac_ceiling` 来自当前请求的有效角色贡献；`resource_ownership_ceiling` 保留原有创建者/管理员限制。`platform_security_ceiling` 是独立的共同安全约束，不用部门禁止动作清单代替。

用户临时 grant 和部门 grant 都不能突破成员路径上限。资源范围匹配只是通过范围，不等于已获得编辑动作或突破所有权。

### 组织共享路径

```text
share_grants = kb_share_declared_actions UNION eligible_user_grants

share_limits =
    receiver_tenant_role_ceiling
    INTERSECT organization_tenant_role_ceiling
    INTERSECT kb_share_permission_ceiling
    INTERSECT source_resource_ceiling
    INTERSECT platform_security_ceiling

share_allow =
    human_session_usable
    AND share_path_gate_pass
    AND resource_scope_pass
    AND action IN (share_grants INTERSECT share_limits)
```

用户范围许可可以满足范围门槛，但不能扩大 share 的动作上限。接收 Tenant admin 并不成为源 Tenant admin；组织角色不独立授予未共享资源。共享撤销后，该路径 gate 失败，不靠旧缓存或人工 grant 延续。

### 共享 Agent 路径

Agent 只提供 KB 的 `view/query`，不提供知识库管理能力：

```text
agent_grants = agent_kb_read_actions UNION eligible_user_grants

agent_limits =
    receiver_tenant_role_ceiling
    INTERSECT organization_tenant_role_ceiling
    INTERSECT agent_share_permission_ceiling
    INTERSECT { view, query }
    INTERSECT source_resource_ceiling
    INTERSECT platform_security_ceiling

agent_allow =
    human_session_usable
    AND agent_path_gate_pass
    AND resource_scope_pass
    AND action IN (agent_grants INTERSECT agent_limits)
```

对于不经组织共享的 Agent 路径，组织角色条件只在该路径实际要求组织关系时适用，不能把无关路径的上限全局求交。Agent 自身的 `run` 与每个 KB 的 `query` 分别判断。

| KB 选择模式 | 解析动作 |
| --- | --- |
| `selected` | 仅选中的 KB 可继续判断，不把选中解释成授权通过 |
| `all` | 动态展开该 Agent 的候选 KB，再逐一经过范围和动作判断 |
| `none` | 无 KB 访问，不能回退到其他 Agent |
| 显式 `agent_id` | 验证该 Agent 及源 Tenant，不匹配直接拒绝此入口 |
| 未指定 Agent | 只合并各合法 Agent 已通过的 KB，不借一个 Agent 的权限补另一个 |

### API Key 路径

```text
api_key_allow =
    api_key_principal_dependency_pass
    AND api_key_path_gate_pass
    AND action IN (
        declared_key_actions
        INTERSECT api_key_tenant_ceiling
        INTERSECT api_key_capability_ceiling
        INTERSECT api_key_resource_scope
        INTERSECT source_resource_ceiling
        INTERSECT platform_security_ceiling
    )
```

`api_key_resource_scope` 以请求资源及动作映射到可用集合。真人 `view`、部门绑定或其他 Key 的 scope 不参与这个计算。Key 的身份依赖、撤销和故障行为见[API Key 依赖](./组织同步与身份状态.md#identity-lifecycle)。

### 合并结果

```text
human_allow =
    human_session_usable
    AND (member_allow OR share_allow OR agent_allow)
```

只合并同一真人请求、同一资源和动作已经通过全部检查的路径；不跨主体合并，不把只读路径组合成编辑能力。显式 Agent 入口选择约束先满足，再使用其允许路径，不能因通用 KB 访问另有 share 而补救指定 Agent 失败。

<a id="special-cases"></a>
## 特殊情况

| 情形 | 动作 |
| --- | --- |
| 多部门 | 按 action 合并当前来源内的有效 grant，逐资源检查范围 |
| 父子部门 | 默认不继承；策略显式开启时仅从父向子传播，并记录命中链 |
| 部门移动 | 旧关系及对应授权失效，新关系重新计算；保留审计 |
| 目标资源不存在 | 生成冲突，不静默忽略或授权给同名资源 |
| 一项授权到期 | 移除该项，继续检查其他有效来源 |
| 人工应急许可 | 明确用户/资源/action/path、授权人、原因、到期时间；同步不能续期或覆盖 |
| 显式 Deny | 一期不引入通用 Deny 策略；账号封禁、suspended 与失效作为独立 gate |
| 部门负责人 | 标记不提升角色，只按已批准的具体范围和动作判断 |

部门负责人编辑自己创建且已绑定的内容可按原有守卫允许。编辑他人内容若被创建者守卫拒绝，记录 `deny_with_gap`，不能为了通过样本放宽核心 RBAC；委托编辑是否新增能力列入[Q2](./阶段交付与待确认问题.md#open-questions)。

应急许可也需通过凭证、路径及动作上限；到期撤销且记录审计，不通过修改外部部门名称授予管理员。

<a id="entry-points"></a>
## 入口接入

所有入口使用同一决策器。服务内部调用也携带主体、来源和动作上下文，不能只在 HTTP 路由中间件检查一次。

| 入口 | 执行动作 |
| --- | --- |
| KB/Agent/知识列表、自动补全 | 先过滤可访问集合，再计算可见数量、分页及名称；不能只隐藏前端行 |
| KB 详情、Document/Chunk/Wiki | 解析源 KB，按具体资源/action 重新判断 |
| 预览、图片与引用代理 | 解析源 KB，检查 `view` 与读权限，不能仅以 URL 或列表已过滤为依据 |
| 原文件下载 | 检查 `download_original` 和源 KB 范围；真人保留现有 Contributor 及 KB 写权限门槛，Viewer 可预览已授权内容但不能下载原文件；API Key 单独按现有 `retrieve/full_access` 能力及 scope 检查，不套用真人角色门槛 |
| hybrid-search、聊天检索、Agent 工具 | 检索前限定允许的 KB 集合；生成引用及输出内容前复核 |
| 显式批量 KB 请求 | 任一请求 KB 越界则整次拒绝，不静默忽略以掩盖客户端错误 |
| 动态 `all` 或省略范围 | 只展开当前授权集合，空集合不默认退回全 Tenant |
| 缓存命中 | 返回前校验当前授权和版本，不把旧允许作为凭证 |
| 流式与后台任务 | 在继续读取/输出新资源前复核，撤销后停止后续访问 |

公司隔离启用时，Tenant RBAC 和公司资源范围必须都强制执行；只记录不拒绝的观察模式不能用于隔离生产配置。同 Tenant 原有快捷放行、组织共享和 Agent all 都需接入范围检查。

缓存键至少包含主体、认证来源、当前/源 Tenant、资源、action、路径及状态/策略版本。身份、成员、共享、范围或策略变更失效对应旧结果；长任务不能永远沿用启动时快照。

P5 按入口建立清单，特别验证隐藏资源不出现在名称、ID、总数、检索结果、引用和下载中。实际接入与集成完成标准统一见[路线图](./阶段交付与待确认问题.md#p4-gate)。

## 决策输出与验证入口

输出 `allow`、`deny` 或 `deny_with_gap`，并记录主体、来源、当前/源 Tenant、路径、资源/action、命中的范围、grant、上限、状态/策略版本及拒绝原因。多路径记录各自结果，不只给一个角色数字。

时效依据使用同步层提供的确认、签发、降级和撤销信息；日志仅保留必要摘要，不输出 Token、Secret 或完整外部身份响应。

固定夹具和矩阵见[权限验证](./validation/权限验证夹具.md)，可复现演算见[验证入口](./validation/验证说明.md)。业务未确认的能力缺口和实施准入只在[路线图](./阶段交付与待确认问题.md#p4-gate)登记。
