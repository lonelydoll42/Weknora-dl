# 设计验证说明

## 运行

在仓库根目录执行，使用 Node.js 内置模块，无需安装依赖：

```bash
node docs/company/validation/validate-docs.cjs
node docs/company/validation/design-counterexamples.cjs
git diff --check
```

`validate-docs.cjs` 检查六份正文和验证 Markdown 的编码、表格、代码块、相对链接及章节锚点，并输出正文压缩统计。比较基线固定为重写前的 `106bb7cafde89c55cad062722445bb083a53cd19`；只统计六份正文，不把迁出的夹具计入正文。

`design-counterexamples.cjs` 是简化的设计模型，不导入应用代码，不连接数据库或身份源。现有 86 项断言覆盖已发现的反例及其边界；运行时列出全部场景，失败返回非零状态。

## 材料入口

| 文件 | 用途 |
| --- | --- |
| [权限验证夹具](./权限验证夹具.md) | 固定用户、角色、来源、共享配置和时间；正式 P4/P5 的预期矩阵 |
| [同步验证用例](./同步验证用例.md) | 状态、旧计划、版本、唯一性、并发、重试与回滚预期 |
| [源码核对依据](./源码核对依据.md) | 对固定源码基线核对过的行为和函数位置 |
| [P0 构建与基础测试记录](./P0构建与基础测试记录.md) | 源码完整性、工具链、实际构建和基础测试结果 |
| `design-counterexamples.cjs` | 自动运行的 86 项简化模型断言 |
| `validate-docs.cjs` | 文档结构、引用及压缩统计检查 |

正文规则分别归[组织同步](../组织同步与身份状态.md)和[权限设计](../权限判断与部门隔离.md)，实施准入只归[路线图](../阶段交付与待确认问题.md#p4-gate)。此目录保存输入、预期和证据，不新增业务规则。

| 固定完整矩阵 | P4/P5 有稳定输入与预期，不由实现补默认角色和时间 | 表中所有场景已经自动执行 |

后续记录新增证据时标明源码提交、输入版本、执行命令、结果和覆盖范围。不能把文档演算数量称为应用单测数，也不能凭这次记录关闭 P0 或 P4。
