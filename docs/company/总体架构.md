# 总体架构

## 系统边界

一期为单主 Tenant 企业接入：企业目录提供员工、部门和身份状态，WeKnora 管理本地账号、空间成员及知识资源。同步方向为外部到本地，不向企业目录回写部门或人员关系。

| 概念 | 系统中的职责 |
| --- | --- |
| Tenant | 资源与空间角色的边界；一期以一个主 Tenant 接收员工投影 |
| 外部部门 | 身份源中的组织关系，也是部门策略的主体 |
| WeKnora Organization | Tenant 之间的协作组织；成员是 Tenant，不是员工 |
| 本地用户 | 登录、会话和资源操作主体；可绑定不同身份源 |
| 外部身份 | 某个身份源中的稳定账号；通过映射关联本地用户 |
| 成员贡献 | 人工或某个身份源提供的角色与能力事实；投影到本地成员 |
| 资源范围策略 | 指定主体可以进入的资源、动作和路径；与角色动作授权分开 |

部门调整不改变知识库所属 Tenant。跨 Tenant 协作使用现有组织或 Agent 共享，并通过源 Tenant 的导出审批控制资源范围，不自动把企业部门映射成协作组织。

## 数据流与职责

```text
企业微信 / LDAP / 其他目录
    -> Provider Adapter
    -> 规范化身份事实
    -> Sync：校验、差异、计划、应用
    -> Mapping + Contribution
    -> WeKnora 用户 / Tenant 成员投影

请求 -> 可信凭证上下文
     -> 权限决策器
     -> 现有 RBAC / 资源归属 / 共享检查
     -> 资源范围判断
     -> 业务读取或写入

同步与权限结果 -> 审计
```

图中的检查组件共同参与决策，执行顺序以[权限判断](./权限判断与部门隔离.md#decision-order)为准。

| 模块 | 输入与输出 | 职责边界 |
| --- | --- | --- |
| Provider Adapter | 外部 API → 规范化部门、用户、关系及证据 | 实现分页、游标、限流、重试提示；不决定本地角色或删除用户 |
| Identity Facts | 规范化结果 → 按来源组织的身份事实 | 保存稳定标识、状态、验证时间与来源版本；不保存完整敏感响应 |
| Identity Mapping | 外部身份 + 本地账号 → 已确认映射或冲突 | 负责匹配证据和绑定历史；不以姓名或邮箱字符串直接接管账号 |
| Sync | 快照 + 当前本地状态 → 不可变计划、变更结果 | 管理审批、版本比较、幂等、应用和补偿 |
| Projection | 已批准变更 → 贡献账本及本地成员 | 只写所属贡献；不解释企业微信 SDK 字段 |
| Permission | 可信主体 + 资源 + 动作 + 路径 → 决策 | 统一解析范围与动作；不直接调用外部目录 |
| Audit | 同步、审批、访问结果 → 脱敏记录 | 关联批次、主体、来源、版本和原因；不记录凭据 |

请求不在访问时实时调用企业目录。目录可用性通过同步产生的验证时间和健康状态进入凭证判断，避免授权请求依赖外部接口延迟。

## 与现有代码的衔接

保留现有认证、Tenant 成员管理、资源归属和共享服务，在其外建立企业身份与策略层。复用的数据结构见[现有表](./数据结构与事务.md#existing-tables)，核对过的函数及限制见[源码证据](./validation/源码核对依据.md)。

实现接入分为两个方向：

1. 同步服务通过既有用户、成员与审计接口投影结果，同时维护独立贡献和版本元数据。
2. 路由和业务服务将资源及动作交给同一个权限决策器，再执行原有操作。列表、详情、检索与 Agent 不各写一套部门判断。

不能仅在现有同 Tenant 知识库判断前增加部门 grant：同 Tenant 原有放行并不表达部门资源范围。也不能替换原有创建者守卫来满足委托编辑。具体授权公式、范围例外和入口要求归属[权限设计](./权限判断与部门隔离.md)。

## 关键选型

| 当前决定 | 原因与后果 |
| --- | --- |
| 单主 Tenant，部门作为外部策略主体 | 保留现有资源归属；组织变化只调整身份关系和范围绑定 |
| 企业微信是第一个 Adapter，而非核心模型 | 规范化接口可接其他目录；权限层不依赖供应商字段 |
| 外部 ID 与本地用户 ID 分开 | 不同来源的同名账号不会串号；允许有证据的多来源绑定 |
| 单向同步，人工操作独立记账 | 避免回写企业目录；撤销某一来源时不会覆盖人工或其他来源 |
| 快照、计划与实际变更分开 | 审批对象固定；可识别旧输入、部分失败和其他写入者 |
| 角色能力与资源范围分开 | 角色能读取不等于可读所有部门资源；动作限制保持路径差异 |
| 复用现有 RBAC、归属与共享上限 | 保留现有权限边界，减少核心代码和上游升级冲突 |
| 密钥只保存引用 | 配置、报告、日志及公开仓库不承载生产凭据 |

外部管理员标记仅为身份属性；同步角色规则定义在[成员投影](./组织同步与身份状态.md#projection)。新登录协议不在当前实施主路径，决策截止点见[待确认问题](./阶段交付与待确认问题.md#open-questions)。

## 模式与配置归属

| 模式 | 输出 | 业务写入 |
| --- | --- | --- |
| `inspect` | 数据质量、范围和完整性报告 | 无 |
| `dry-run` | 映射、差异、冲突和拟执行计划 | 无 |
| `apply` | 已批准计划的逐项执行结果 | 有，按对象事务 |
| `reconcile` | 完整对账后生成并执行的受控计划 | 有，沿用同一应用协议 |

P1/P2 使用脱敏文件和内存模型；持久化及写入何时开放只由[路线图](./阶段交付与待确认问题.md#stages)规定。`reconcile` 不是绕过审批、版本或撤销检查的快捷入口。

配置分三类管理：身份源配置归 Adapter/Sync，部门和导出策略归 Permission，角色与资源管理归 WeKnora。配置变更发布新版本；计划和缓存消费该版本，不读取可被管理员原地修改而无版本记录的规则。

业务数据仍归原有模块管理。企业化层不复制知识库、文档或 Agent 表，也不通过同步任务删除用户的历史内容。

## 实施边界

模块之间传递规范化对象、稳定 ID、版本和证据引用，不传递 SDK 对象或原始 Secret。字段与索引以[数据库设计](./数据结构与事务.md)为准；身份状态、凭证失效和故障恢复以[同步设计](./组织同步与身份状态.md)为准。

功能通过 feature flag 分阶段启用，灰度时允许对决策做对比观测，但公司隔离的正式执行要求由[入口接入](./权限判断与部门隔离.md#entry-points)规定。多 Tenant 企业模式、委托编辑和登录接入只能在对应阶段重新评审，不从本架构图推导额外能力。
