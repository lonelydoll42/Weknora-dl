# 阶段交付与待确认问题

<a id="stages"></a>
## 实施顺序

```text
P0 基线与运行验证
  -> P1 只读采集
  -> P2 内存映射与计划
  -> P3-A 必要持久化与撤销
  -> P3-B 受控成员投影
  -> P4 权限计算 POC
  -> P5 ACL 与真实入口
  -> 登录接入、生产化、上游同步
```

当前处于 P0：源码/Git 基线和静态设计已完成，构建、基础测试及关键业务确认未完成。设计反例演算不表示 P4 完成。阶段完成标准未满足时，不开始下一阶段功能；当前只改文档和设计验证材料。

| 阶段 | 做什么 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| P0 | 核实源码共同祖先、构建、基础测试及企业边界 | 可复现基线、运行记录、确认事项 | merge-base 可查；构建和基础测试实际通过；单 Tenant、来源与安全边界确认；公开仓库范围确定 |
| P1 | Adapter 拉取、分页、规范化和完整性校验 | 脱敏固定样本、采集报告、失败报告 | 固定/真实脱敏样本可重复；末页、中断、树循环和范围缩小测试明确；业务库零写入 |
| P2 | 内存匹配、差异与不可变计划 | 候选映射、冲突清单、审批输入 | 不串号/重复建用户；邮箱双侧证据验证；每项关联批次；旧输入、目标变更、过期审批可识别 |
| P3-A | 最小身份/版本/计划持久化与可信来源、撤销协调 | 独立迁移、撤销接口、并发验证记录 | 两向 active 唯一、rebind 历史及来源可校验；全部旧凭证撤销与并发签发验证；旧计划和 ABA 回归通过 |
| P3-B | feature flag 下贡献与 `tenant_members` 投影 | dry-run/apply/rollback、审计与补偿 | 仅确认 active 映射参与；不覆盖人工或其他来源；CAS 冲突停批；部分结果与回滚可查询 |
| P4 | 固定输入的纯策略计算器，不改路由 | 决策矩阵、重复演算、缺口记录 | 满足下述 P4 门槛，并由业务与权限/安全评审人确认 |
| P5 | 获准范围内 ACL、绑定迁移与入口接入 | 路由清单、实际 HTTP/集成回归、灰度开关 | 所有声明入口覆盖；隐藏资源不泄露；撤销、缓存、流式、后台任务验证；无缺口能力才可交付 |

P1/P2 不写 `users`、成员或身份表；P3-A 不一次性建齐完整外部快照。P5 之前不改现有 RBAC 中间件、不加部门 ACL 路由或权限绑定迁移。

<a id="p4-gate"></a>
## P4 准入与 P5 范围

P4 输出每项 `allow`、`deny` 或 `deny_with_gap`，包含主体/来源/路径、资源/action、范围命中、grant、上限、版本与时间依据。

通过检查：

1. 未授权放行、已确认应允许的误拒绝、失效/撤销/过期后继续放行都为 `0`。
2. 不保留 `unknown`；全部预期由输入夹具固定，不能根据演算结果反向改预期。
3. 连续两次结果、命中来源、原因和计数一致。
4. 矩阵覆盖范围、角色、所有权、组织共享、Agent、Key、多身份源、时间边界和同步版本。
5. 缺口记录由业务负责人和权限/安全评审人共同批准；开发人员单独确认不代表接受。

| 评审结果 | 判定 | 后续范围 |
| --- | --- | --- |
| `fail` | 有越权、误拒绝、失效后放行、unknown 或未批准缺口 | 不进入 P5 |
| `security_pass_with_gap` | 安全判断正确，仍存在已批准的能力缺口 | P5 只实现无缺口 capability；缺口能力不实施、不发布 |
| `pass` | 声明范围全部结果确认，无未决缺口 | 可进入完整 P5 评审 |

`deny_with_gap` 记录描述、影响资源/action、临时限制、责任人和复核日期。委托编辑未具备时不作为已交付能力，不放宽核心守卫来消除演算中的拒绝。

P5 不能仅凭计算器结果发布：要按[入口清单](./权限判断与部门隔离.md#entry-points)验证真实列表、详情、子资源、检索、Agent、引用、下载、缓存和长任务。未接入或未验收的入口/能力保持关闭；`security_pass_with_gap` 本身不授权生产发布。

## 待确认问题

下表是唯一待定事项清单。“决定时间”按阶段截止，阶段未关闭前必须记录批准结论、责任人和日期。当前设计决定继续用于演算，不能把尚未批准的生产参数直接上线。

| 编号 | 当前决定 | 待确认内容与影响 | 决策角色 | 决定时间 |
| --- | --- | --- | --- | --- |
| Q1 | 演算时效窗口 24h | 生产窗口、恢复核对及告警策略；影响故障时可用性与失效传播时限 | 业务 + 安全 + 运维 | P0 关闭前 |
| Q2 | 保留创建者/管理员守卫 | 是否新增受控委托编辑；影响负责人编辑他人内容及 P4 缺口范围 | 业务 + 权限/安全 | P4 开始前 |
| Q3 | 单来源失效不推断全局封禁 | 全局离职事件和本地封禁策略；影响多来源用户重新认证 | 业务 + 身份管理员 | P0 关闭前 |
| Q4 | 复用现有 Token 撤销并保留可信来源 | 并发签发/刷新是否需额外用户级版本；会话字段与持久化屏障的位置 | 后端 + 安全 | P3-A 评审前 |
| Q5 | 一个主 Tenant，范围与动作分离 | 公共资源、人工管理例外、导出审批及新资源绑定模板的业务配置 | 业务 + 权限/安全 | P4 开始前 |
| Q6 | 逻辑结构先于物理实现 | 生产数据库、active 唯一索引方案、贡献/版本记录复用位置 | 后端 + 数据库负责人 | P3-A 迁移前；权限结构在 P5 迁移前 |
| Q7 | 最小数据、Secret 引用、脱敏诊断 | 保留期、证明摘要访问与删除策略；影响历史审计及隐私 | 安全 + 数据负责人 | 首次持久化前 |
| Q8 | 独立机器 Key 保持现有模型 | 是否实施用户绑定 Key、能力范围和依赖存储；影响额外迁移及撤销验证 | 业务 + 后端 + 安全 | P3-A 撤销评审前确定范围；纳入时迁移前确认 |
| Q9 | 登录协议不在当前主路径 | 企业微信 OAuth、统一 OIDC 或现有账号登录；影响来源证明及账号首次绑定 | 身份管理员 + 后端 | 登录阶段启动前 |
| Q10 | 沿用仓库部署/开发入口 | 目标运行环境、构建链、Docker/数据库可用性及基本回归 | 后端 + 运维 | P0 关闭前 |

新问题只加入此表并说明影响、决策角色与截止点；对应正文写当前决定并链接编号，不在各段重复候选方案。

## 后续交付

登录接入在映射与撤销稳定后单独立项，交付首次登录、来源证明、账号绑定/冲突、失败脱敏和失效后的真实会话回归。

生产化交付定时/手动任务、锁与超时、退避重试、对账、监控告警、审计、补偿、灰度和紧急停用开关，并实际演练恢复与备份。安全事件响应与常规同步任务分开观察，不能因常规审批积压延迟失效阻断。

上游同步记录源提交及迁移差异，重点回归认证、Token、Tenant 成员、资源归属、共享、Agent 和 Key 的变化。公司逻辑保持在适配与扩展边界内，不将内部部署配置同步到公开源仓库。

## 协作与提交

使用 `<type>/<topic>` 分支名称，沿用 `docs/company-org-permission` 设计分支，不新增 `codex/` 前缀。功能在阶段准入后进入独立分支，提交前确认源码共同祖先和当前远程状态，不改无关文件。

`origin` 是公司二开公开 Fork，`vendor` 是来源仓库。公开文档只用脱敏样本；生产凭据和保密材料放受控私有位置。推送不使用 force，主分支保持独立，vendor 不直接写入公司功能。

提交说明用中文，列出变更范围、规则归属调整、实际验证及未验证项。审查经过和逐轮修订放提交说明或验证记录，不再进入设计正文。
