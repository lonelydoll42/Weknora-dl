# 数据结构与事务

本文定义实施需要的逻辑记录、关联、索引与写入要求。具体物理表和迁移按[阶段计划](./阶段交付与待确认问题.md#stages)评审；状态变化由[同步设计](./组织同步与身份状态.md)定义，访问规则由[权限设计](./权限判断与部门隔离.md)定义。

<a id="existing-tables"></a>
## 现有表

| 表 | 继续承担的职责 | 企业化写入边界 |
| --- | --- | --- |
| `users` | 本地账号与用户主体 | 仅更新获批字段，不直接存部门数组 |
| `tenant_members` | 用户在空间的物化成员角色 | 由贡献账本生成，管理与同步写入同时维护归属 |
| `organizations` | 跨 Tenant 协作组织 | 不复制成企业部门 |
| `organization_tenant_members` | 组织中的 Tenant 关系 | 由组织共享流程管理 |
| `kb_shares` | 知识库共享 | 不代替部门资源绑定 |
| `tenant_api_keys` | 机器凭证 | 复用 Key 状态，普通同步不创建 Key |
| `audit_logs` | 变化与操作审计 | 关联 run、plan、change 和决策摘要 |

企业身份与贡献记录独立于业务资源表。完整外部快照不是所有阶段必需的数据；但进入写入阶段前，版本、验证时间、归属和撤销协调元数据必须可持久化。

## 通用字段约定

| 字段类别 | 存储约定 |
| --- | --- |
| 本地 ID / 引用 | 沿用仓库 ID 类型；引用明确目标对象，删除重建使用新身份 |
| 外部 ID | 不透明字符串，始终带 `provider_id`；不从数字大小推导顺序 |
| 状态 | 有限枚举，由所属设计文档约束转换，不用空值代替状态 |
| 时间 | 带统一时区语义的时间点；验证、签发、审批、更新各字段分开 |
| 版本 | 单调递增整数或等价可比较版本；任何写入者都维护 |
| 证据、审批、配置引用 | 受控引用或摘要，不含完整敏感响应及明文 Secret |
| 动作集合 | 可校验的资源类型/action 集合，不存任意可执行表达式 |

需要变更追踪的记录共同带 `record_version`、`last_change_id`、`created_at`、`updated_at`。按字段并发的目标另保存 `field_version` 与字段所有者。下列字段表不重复列通用时间戳。

版本不因 rollback、游标重置或数据迁移减小。对象删除重建不能复用旧 ID/版本组合，旧计划不能命中新对象。所有人工、同步和补偿写入路径均更新版本与变更归属，不能只在同步服务中维护。

<a id="identity-tables"></a>
## 身份记录

### `identity_providers`

| 字段 | 含义 |
| --- | --- |
| `id`、`provider_type`、`issuer_key` | 身份源实例及企业/issuer 标识 |
| `config_ref`、`config_version` | 受控配置引用及版本 |
| `status`、`degraded_at`、`max_stale_age` | 来源健康与时效配置 |
| `current_snapshot_version`、`scope_version` | 已接受快照及当前可见范围版本 |
| `last_success_at` | 健康报告使用，不代替用户验证时间 |

唯一索引：`(provider_type, issuer_key)`。健康周期历史写审计记录，当前 `degraded_at` 不兼作历史列表。普通查询接口不能展开 `config_ref` 中的密钥。

### 部门、用户与关系

| 记录 | 必要业务字段 | 主键/唯一键与索引 |
| --- | --- | --- |
| `identity_departments` | `id, provider_id, external_id, parent_external_id, name, status, snapshot_version` | unique `(provider_id, external_id)`；index `(provider_id, parent_external_id)`、`(provider_id, status)` |
| `identity_users` | `id, provider_id, external_user_id, status, visibility_state, last_verified_at, snapshot_version, security_event_version` | unique `(provider_id, external_user_id)`；index `(provider_id, status)` |
| `identity_user_departments` | `provider_id, external_user_id, external_department_id, is_primary, status, last_verified_at, snapshot_version` | unique 三元组；按用户查部门、按部门查用户的组合索引 |

部门父节点必须属于同一 provider，根节点有明确表达，导入前检查无环。用户部门关系关联同来源的已有用户/部门；不能仅靠 JSON 中的部门 ID 列表维护关系。

显示名、外部管理员标记等只在适配/管理展示确有需求时作为属性保存，不加入授权主键。未批准的手机号、原始响应等不进入业务表。

`visibility_state` 与 `status` 分开存储。删除证据引用通过批次/安全事件关联；`last_verified_at` 和 `security_event_version` 的更新动作使用[同步定义](./组织同步与身份状态.md#freshness)，不能由普通本地更新时间代替。

### `identity_mappings`

| 字段 | 含义 |
| --- | --- |
| `id, provider_id, external_user_id, local_user_id` | 稳定绑定身份 |
| `status, match_method` | active/conflict/revoked 与匹配方式 |
| `ownership_proof_ref, bound_at, revoked_at` | 归属证据及绑定生命周期 |
| `supersedes_mapping_id, rebind_reason` | 新绑定与旧记录的历史关联 |
| `last_verified_at, last_sync_run_id` | 可靠验证时间与关联批次 |

索引和约束：

```text
unique active(provider_id, external_user_id)
unique active(provider_id, local_user_id)
index(local_user_id, status)
```

唯一性针对 active 集合，不阻止 revoked 历史保留；`local_user_id` 不全局唯一。数据库支持 partial/filtered unique index 时使用该约束，否则采用锁定的 active 关系记录或等价事务方案，同时覆盖两个方向。

mapping 的用户和 provider 必须存在，历史引用不能级联删除审计。revoked 记录不可原地改回 active，新记录通过 `supersedes_mapping_id` 关联历史；生命周期动作只按[同步规则](./组织同步与身份状态.md#identity-lifecycle)执行。

## 批次、计划与变更

这些逻辑记录可以按仓库模式合并物理存储，但各版本、审批和执行结果必须可单独校验。

| 记录 | 必要字段 | 关联与索引 |
| --- | --- | --- |
| `identity_sync_runs` | `id, provider_id, mode, cursor, status, started_at, ended_at, snapshot_version, scope_version, config_version, complete, completeness_evidence_ref, counters` | index `(provider_id, snapshot_version)`、`(provider_id, status)` |
| `SyncPlan` | `plan_id, run_id, provider_id, snapshot_version, scope_version, config_version, policy_version, plan_hash, approval_ref, approval_expires_at, status` | index `(provider_id, status)`；关联生成批次 |
| `SyncChange` | 下表的输入、目标和执行字段 | unique `idempotency_key`；index `(plan_id, status)`、`(target_type, target_id, field)` |
| `identity_sync_errors` | `id, run_id, object_type, external_id, error_code, retryable, message_safe, attempt_count` | index `(run_id, retryable)` |

| `SyncChange` 字段组 | 字段 |
| --- | --- |
| 对象与差异 | `change_id, plan_id, target_type, target_id, field, before, after` |
| 来源版本 | `source_record_version, security_event_version` |
| CAS 输入 | `expected_record_version, expected_field_version, expected_owner, expected_last_change_id` |
| 执行输出 | `post_record_version, post_field_version, idempotency_key, status, error_ref` |

输入、before/after 和审批 hash 一经批准不可改写；执行状态与 post 版本另存。批次 counters 仅为汇总，逐项结果才是重试/补偿依据。完整性证据包括终止页/游标和范围核查摘要，不保存整份企业响应。

`idempotency_key` 覆盖来源、对象、计划变更和操作身份，不能只使用用户 ID 或当前值。相同 key 已应用时返回历史结果，不新建第二份贡献；被后续覆盖后的行为按[应用协议](./组织同步与身份状态.md#apply)处理。

## 贡献账本与投影

`tenant_members` 每用户/空间只有一条物化关系，来源归属使用独立贡献记录：

```text
contribution_id
local_user_id, tenant_id
source_type = manual / provider
provider_id, mapping_id
role_or_capabilities, status, owned_fields
record_version, last_change_id
```

外部贡献的 provider 和 mapping 必填且匹配；人工贡献不伪造外部 provider。授权读取按来源筛选贡献，不仅使用物化成员的最高角色。

建议索引：`(local_user_id, tenant_id, status)`、`(provider_id, mapping_id, status)`；同一来源、主体和贡献槽位的有效记录唯一。人工 suspended 作为独立状态/阻断记录，不能被最高角色计算覆盖。

物化成员写入引用产生它的贡献版本；账户创建、成员变更、人工管理与同步更新都参与版本维护。审计可从最终成员状态反查每项贡献及所属 change。

<a id="permission-tables"></a>
## 权限记录

以下结构服务于 P5 的 ACL 实现；其准入由[路线图](./阶段交付与待确认问题.md#p4-gate)决定，不由 P3 成员持久化顺带创建。

### `permission_bindings`

| 字段组 | 字段 |
| --- | --- |
| 主体 | `subject_type, provider_id, subject_ref` |
| 目标 | `tenant_id, resource_type, resource_id` |
| 权限 | `capabilities, access_path, scope_grant` |
| 归属与生效 | `source, valid_from, valid_until, status, created_by, approval_ref` |
| 追踪 | `id, record_version, last_change_id` |

`external_department` 主体使用 `provider_id + subject_ref`，provider 必填；`local_user` 主体用本地用户 ID，provider 不参与主体匹配。查找、唯一约束和审计不得只使用裸部门 ID。

索引覆盖主体及有效状态、目标资源及有效状态、到期时间。有效绑定的唯一键须包含策略来源与路径，不能将人工和同步记录折叠成同一行。目标 Tenant 和资源必须存在且一致。

`capabilities` 与 `scope_grant` 分开表达。资源/action/path 的范围匹配及 grant 限制按[权限公式](./权限判断与部门隔离.md#grants-and-limits)解释；不增加通用 `deny` 字段，也不从空 capability 推断拒绝覆盖规则。

### 资源范围与导出

| 记录 | 必要字段 | 约束 |
| --- | --- | --- |
| ResourceScope | `tenant_id, resource_type, resource_id, scope_mode, public_actions, policy_version` | unique 资源键；scope_mode 为 restricted/tenant_public |
| ApprovedExport | `source_tenant_id, resource_id, receiver_tenant_id, access_path, organization_id/agent_id, actions, approval_ref, valid_until, status` | 目标资源属于源 Tenant；路径目标匹配；按接收方/路径/资源索引 |

两类记录都带通用版本和变更 ID。内部企业归属由身份与成员贡献提供，不从当前 Tenant 推导；资源范围表不复制一份独立员工目录。

创建 KB 与初始 ResourceScope/绑定在同一事务提交。子资源通过现有关系解析源 KB，不在每个 Chunk 重复存一份可漂移的部门策略。

## 凭证元数据

可信会话至少承载 `local_user_id, authn_method, authn_provider_id, identity_mapping_id, issued_at, active_tenant_id, revocation_reference`。优先复用 AuthToken 存储及现有撤销接口；物理字段扩展和并发屏障方案列入[Q4](./阶段交付与待确认问题.md#open-questions)。

用户绑定 Key 若纳入实施，另记录 `key_id, principal_type, local_user_id/service_principal_id, dependency_provider_id, dependency_mapping_id, record_version`。Key 创建者不替代依赖关系；独立机器 Key 无个人依赖。该关系的具体迁移需在[Q8](./阶段交付与待确认问题.md#open-questions)确定后提交。

用户级撤销屏障须持久化且能被所有认证/签发路径读取；不能只存进程内变量或缓存。凭证生命周期只使用[同步协议](./组织同步与身份状态.md#identity-lifecycle)，不在此表设计重复定义。

<a id="transactions"></a>
## 事务与并发要求

| 操作 | 原子写入或协调范围 |
| --- | --- |
| 接受来源快照/安全事件 | 来源版本、对象事实、证据引用与安全版本；和 provider apply 串行协调 |
| 应用单个对象 | CAS 条件、贡献、成员投影、SyncChange post 版本及审计同一对象事务 |
| 人工改角色/字段 | 对应贡献或字段所有者、目标版本、last_change_id 与审计 |
| 用户撤销 | 状态与凭证同事务，或先持久化屏障再完成撤销；细节见同步协议 |
| 创建 KB | 资源及初始范围/绑定同事务，任一失败全部不提交 |
| 回滚单项 | post 版本与归属 CAS、新目标版本、回滚 change 和审计 |

provider 互斥不能代替目标 CAS；锁释放前需保存执行结果。跨对象批次不要求大事务，已完成项持久化，失败项不得伪报成功。

批准后的计划内容与执行状态分离，避免执行状态更新改变审批 hash。源事实在执行期间变化时，相关 CAS 或协调锁必须能阻止旧项写入；只做一次开始时检查不足。

必要状态查询失败时业务层拒绝依赖该状态的访问；数据库读失败不能被“查无记录”处理成默认 public 或默认 active。

## 迁移与保留

P3-A 先提交映射、必要来源事实及版本、计划和撤销协调的最小迁移；P3-B 接入贡献与成员投影。完整目录快照按实际对账需求引入，P5 再迁移权限及范围结构。

迁移使用仓库 versioned migration，提供 up/down，明确 SQLite、PostgreSQL/ParadeDB 和 MySQL 支持范围。先建结构与索引，再接入读路径，最后开启写路径；不直接改核心初始化 SQL。评审 active 唯一索引的等价实现、大表锁定、失败回滚和旧版本兼容。

只保存匹配、时效、对账和审计需要的数据。配置引用、证明摘要按权限读取；诊断缓存自动到期，错误日志脱敏。身份历史、审计和诊断保留期由[Q7](./阶段交付与待确认问题.md#open-questions)确定，不把未决定的手机号、完整响应或额外展示字段预建进表。
