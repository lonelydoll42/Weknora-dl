# 企业组织同步与权限开发文档

## 目标

在 WeKnora 中接入企业目录，完成员工身份映射、成员同步和部门资源隔离。一期采用一个主 Tenant，先接企业微信，再复用同一接口接入其他身份源；部门不自动创建 Tenant 或 WeKnora Organization。

现有 Tenant RBAC、资源归属和组织共享继续使用。部门隔离增加独立的资源范围判断，不用部门授权并集代替隔离。

## 当前进度

当前交付为设计文档和可复现的设计演算，尚未实现组织同步、部门 ACL 或数据库迁移。已完成源码静态核对；构建、基础测试、真实身份源和 HTTP 集成验证尚未完成，阶段状态见[路线图](./阶段交付与待确认问题.md#stages)。

文档正文记录当前设计决定。待定事项只在[待确认问题](./阶段交付与待确认问题.md#open-questions)登记，测试夹具、源码证据和验证结果放在 `validation/`，不作为运行实现已完成的证明。

## 启动方式

以下命令在仓库根目录执行，运行的是已有 WeKnora 基线。先按[中文项目说明](../../README_CN.md)配置 `.env`；实际部署配置以仓库现有说明为准，不使用文档夹具中的账号和时间参数。

**运行容器基线**

使用 Docker Compose；Windows 使用 Docker Desktop Linux 引擎。先执行 `docker version`，确认输出包含 Server，再继续。没有 `.env` 时从 `.env.example` 创建，已有配置不得覆盖：

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
docker compose config --quiet
docker compose up -d
```

完整部署步骤、镜像更新和访问地址见[中文项目说明](../../README_CN.md)。本次文档修订未启动 Docker 或验证服务可用性。

**开发本地源码**

在具备仓库要求的 Go、Node、Make 和 Bash 的环境中执行，Windows 可在已配置的 WSL 环境运行。依赖、后端、前端各用一个终端：

```bash
make dev-start
make dev-app
make dev-frontend
```

这些目标调用现有 `scripts/dev.sh`，详细配置见[快速开发模式说明](../快速开发模式说明.md)。容器镜像启动与本地源码开发是两种运行方式，不能用镜像运行结果验证尚未接入的二开代码。
